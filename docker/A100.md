# Chạy public test trên 1 × A100 80 GB

Nếu dùng **2 RTX 5090 / 600 câu**, xem [profile RTX5090 hướng tới 6 giờ](RTX5090.md).

Worker hỗ trợ một A100 khi truyền `DATAMATE_PROFILE=balanced` cùng
`DATAMATE_TENSOR_PARALLEL=1`. Mặc định mới là profile `rtx5090-2gpu-6h` cho hai GPU.
Cùng Qwen local xử lý manifest, SQL và review;
ingestion/DuckDB chạy trên CPU. Cấu hình thực tế được lưu ở `logs/run.json`.

Hướng dẫn dành cho server Linux x86_64, GPU A100 đầy đủ (không phải MIG slice).
A100 nằm trong danh sách GPU hỗ trợ của [vLLM](https://docs.vllm.ai/en/latest/getting_started/installation/gpu/).
Chưa benchmark image này trên A100: cần chạy kiểm tra bên dưới và toàn bộ dataset
để xác nhận bộ nhớ, tương thích kernel và thời gian. Giới hạn gần 6 giờ của worker
vẫn áp dụng; những câu chưa xử lý giữ `abstain`.

## 1. Chuẩn bị server

Chép phiên bản mã nguồn có tùy chọn một GPU này lên server, rồi `cd` vào repo.
Nếu clone từ GitHub, cần chắc rằng thay đổi đã có trên commit được clone.
Các khối lệnh bên dưới chạy trong Bash, từ thư mục gốc repo, cùng một phiên shell.
Nên mở `tmux new -s datamate` sau khi SSH vào server; dùng `tmux attach -t datamate`
để quay lại phiên khi kết nối SSH bị ngắt. Máy cần có `tmux` trước khi dùng lệnh này.

```bash
uname -m
nvidia-smi
docker version
nvidia-ctk --version
python3 --version
df -h . /var/lib/docker
```

Cần Docker Engine và NVIDIA Container Toolkit. Nếu chưa có Toolkit, làm theo
[hướng dẫn NVIDIA](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
Sau khi cài Toolkit, cấu hình Docker như sau (restart có thể ảnh hưởng container
khác đang chạy trên server):

```bash
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

Driver host phải tương thích CUDA trong image. Không suy ra phiên bản CUDA của
PyTorch từ dòng `CUDA Version` của `nvidia-smi`; kiểm tra trực tiếp ở bước 3.
Image cung cấp PyTorch/vLLM/CUDA runtime, không cần cài chúng vào Python host.
Dành dung lượng cho weights, build cache, image và logs; nếu export cần thêm
dung lượng cho archive. Các file này có thể chiếm hàng chục GB mỗi loại.

## 2. Tải model và build (cần Internet)

Bỏ qua tải model nếu `models/Qwen3.5-9B/` đã chứa weights và
`MODEL_MANIFEST.json` được tạo bởi `docker.prepare_model`.
Python host cần >= 3.11 vì bước kiểm kê weights sử dụng `hashlib.file_digest`.
Chỉ cần môi trường tải model trên host; các requirements inference được Dockerfile
cài từ `docker/requirements.txt` vào image.

```bash
python3 -m venv .venv-model
.venv-model/bin/pip install huggingface_hub
# Lấy một revision thật trước hạn, có weights, rồi lưu SHA để tái lập.
HF_HUB_OFFLINE=0 TRANSFORMERS_OFFLINE=0 HF_DATASETS_OFFLINE=0 \
  .venv-model/bin/python - <<'PY'
from datetime import datetime, timezone
from pathlib import Path
from huggingface_hub import HfApi
revision_file = Path('.venv-model/model_revision.txt')
revision_file.unlink(missing_ok=True)
api = HfApi()
repo = 'Qwen/Qwen3.5-9B'
cutoff = datetime(2026, 10, 26, tzinfo=timezone.utc)
commits = sorted(api.list_repo_commits(repo), key=lambda c: c.created_at, reverse=True)
for commit in commits:
    if commit.created_at >= cutoff:
        continue
    if any(name.endswith('.safetensors') for name in api.list_repo_files(repo, revision=commit.commit_id)):
        revision_file.write_text(commit.commit_id + '\n')
        print('Selected model revision:', commit.commit_id, commit.created_at)
        break
else:
    raise RuntimeError('Không tìm được revision có weights trước hạn')
PY
```

Chỉ tiếp tục khi lệnh trên thành công. Không tự điền một chuỗi 40 ký tự làm SHA.
Nếu đã có revision đóng băng được xác minh, dùng lại SHA đó thay vì chọn lại.

```bash
MODEL_REVISION="$(cat .venv-model/model_revision.txt)"
HF_HUB_OFFLINE=0 TRANSFORMERS_OFFLINE=0 HF_DATASETS_OFFLINE=0 .venv-model/bin/python -u -m docker.prepare_model --revision "$MODEL_REVISION"
```

Nếu terminal hiện dấu nhắc `>` thay vì chạy, Bash đang chờ hoàn thành một lệnh
chưa đóng (thường do ký tự `\\`, dấu nháy hoặc here-document bị dán thiếu).
Nhấn `Ctrl+C` để về dấu nhắc shell bình thường, rồi dán **nguyên một dòng**
`HF_HUB_OFFLINE=0 ... "$MODEL_REVISION"` phía trên. Không dán dấu chấm hay
ký tự `\\` ở cuối lệnh. `prepare_model` sẽ in các mốc kiểm tra revision,
kiểm tra ngày phát hành, bắt đầu tải và kiểm kê. Việc kiểm tra lịch sử commit
có thể mất một lúc trước khi xuất hiện thanh tiến trình tải weights.

Chờ tải model và tạo `MODEL_MANIFEST.json` thành công rồi mới build:

Nếu gặp `OfflineModeIsEnabled` / `offline mode is enabled`, shell hoặc môi trường
server đang bật offline cho Hugging Face. Các tiền tố `...OFFLINE=0` trên chỉ áp dụng
cho từng lệnh chuẩn bị model và được đặt trước khi import thư viện. Không cần sửa
`Dockerfile` hay `predict.sh`: inference vẫn offline. Bước chuẩn bị cần Internet
thật; đặt biến về `0` không cấp mạng cho container chạy với `--network none`.

```bash
export IMAGE=zaic2026_datamate_aio_dncoming:final
docker build --platform linux/amd64 -t "$IMAGE" .
```

Chạy các lệnh trong Bash. Chọn revision có đầy đủ weights; script kiểm tra
licence, ngày phát hành, số tham số và checksum. Không dùng `main` làm revision.
Build cũng cần `dataset/train` để đóng gói dữ liệu xác minh theo guideline.
Weights được COPY vào image; lúc inference không cần mount thư mục model.
Tên repository của image phải viết thường; dùng cùng tên ở bước build, run và export.

## 3. Kiểm tra CUDA trong image

```bash
export IMAGE=zaic2026_datamate_aio_dncoming:final
docker run --rm -i --gpus '"device=0"' --network none \
  --entrypoint python3 "$IMAGE" - <<'PY'
import torch
from docker.worker import gpu_preflight
print(gpu_preflight(torch, 1))
print('VRAM GiB:', torch.cuda.get_device_properties(0).total_memory / 2**30)
PY
```

Phải nhận diện A100 và chạy được phép nhân BF16. Đây là kiểm tra CUDA ban đầu;
khởi tạo Qwen/vLLM và full inference vẫn cần vượt qua bước 4.

## 4. Chạy toàn bộ public test offline

Thư mục input cần chứa `questions.jsonl`, `rulebook.md`, `calendar.csv`, `data/`.
Worker tạo manifest và DuckDB mới từ dữ liệu gốc, rồi trả lời câu hỏi. Không cần
chạy Colab hoặc ingestion trước. Worker không đọc `answers.jsonl`.

```bash
export IMAGE=zaic2026_datamate_aio_dncoming:final
export INPUT_DIR="$PWD/dataset/public_test"
export RESULT_DIR="$PWD/result_a100_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$RESULT_DIR"
set -o pipefail
docker run --rm --gpus '"device=0"' --network none --shm-size=16g \
  -e DATAMATE_PROFILE=balanced \
  -e DATAMATE_TENSOR_PARALLEL=1 \
  --entrypoint bash \
  -v "$INPUT_DIR:/data:ro" \
  -v "$RESULT_DIR:/result" \
  "$IMAGE" /code/predict.sh 2>&1 | tee "$RESULT_DIR/console.log"
```

Dùng `tmux` nếu chạy qua SSH để tránh ngắt phiên. GPU cần đủ bộ nhớ trống;
vLLM mặc định dùng tỷ lệ `gpu_memory_utilization=0.88`. Không cần Gemini API key.
Để thử trên train, đổi duy nhất `INPUT_DIR` thành `$PWD/dataset/train`.

Kết quả nằm ở `$RESULT_DIR/submission.jsonl`; log từng câu ở
`$RESULT_DIR/logs/question_*.json`. Các mốc pipeline (nạp model, tạo manifest,
ingestion, từng câu và hoàn tất) hiện trực tiếp trên terminal, được `tee` vào
`console.log` và ghi dạng JSONL ở `$RESULT_DIR/logs/progress.jsonl`. Khi SSH
qua `tmux`, có thể xem tiến độ ở terminal khác bằng
`tail -f "$RESULT_DIR/logs/progress.jsonl"`. Theo dõi GPU bằng
`watch -n 2 nvidia-smi`. Xem `console.log`, `logs/run.json`, `logs/completion.json`
và `logs/fatal.json` nếu có. Submission được tạo trước khi model load, vì vậy
**có file submission không đồng nghĩa pipeline đã chạy xong**. Kiểm tra các log
pending, preparation_failed và deadline_reached để biết phần chưa hoàn thành.
Chạy lại phải dùng thư mục kết quả mới; worker không resume từ lần trước.
DuckDB tạm nằm trong `/tmp` container và bị xóa khi kết thúc; chỉ submission/log
được giữ trong thư mục result.

## 5. Chạy theo cấu hình BTC

Trên máy hai GPU, bỏ `-e DATAMATE_TENSOR_PARALLEL=1`, đổi profile thành
`-e DATAMATE_PROFILE=rtx5090-2gpu-6h` và đổi thành `--gpus '"device=0,1"'`.
Mặc định frozen config là TP=2. Tùy chọn TP=1 phục vụ
server A100; không yêu cầu BTC truyền biến môi trường. Kết quả A100/TP=1 chưa
chứng minh tốc độ hay reproducibility trên RTX 5090/TP=2: cần benchmark và đo
chênh lệch PA trên cấu hình BTC trước khi nộp. Xem [README](README.md) để export.
Với tên image trong hướng dẫn này, lệnh export là
`bash docker/export.sh aio_dncoming ./release`.

Lỗi thường gặp:

- `Worker requires 2 CUDA GPU(s)`: với A100 đơn, dùng `-e DATAMATE_PROFILE=balanced -e DATAMATE_TENSOR_PARALLEL=1`.
- `could not select device driver`: Docker chưa được cấu hình NVIDIA Toolkit.
- Lỗi driver/CUDA hoặc kernel: kiểm tra driver host và bước 3; không tự thay torch
  trong image vì có thể làm lệch ABI với vLLM.
- OOM: kiểm tra tiến trình khác chiếm VRAM và GPU/MIG được cấp thực tế.
- Build không thấy model: chạy bước tải weights trước, từ đúng repo root.
